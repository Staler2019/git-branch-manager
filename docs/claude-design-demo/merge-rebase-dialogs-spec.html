Merge & Rebase Dialogs

從分支列「⋮」點 Merge into current / Rebase current onto here 時，被點的分支已經是答案， 對話框不該再讓人選；從 Branch 選單或快捷鍵進來時才需要選，而選的那個控制項要換成 app 既有的 GbmRefPicker，不是 Material 下拉。

使用者回報 · 分支列進入不該再選 使用者回報 · 下拉樣式不對 使用者裁定 · Merge 訊息預填 使用者裁定 · Merge 來源含 origin 使用者裁定 · ①③④⑤⑥⑦ 照建議、⑧ 一起做 使用者裁定 · ⑨ SQUASH_MSG、無衝突才 commit 設計稿通過才開工

#問題本稿提案
①05-E commit 列的 Rebase onto here 也鎖定？使用者裁定 2026-10-08：「1,3,4,5,6,7照你建議，8一起做」。是（03-C）。同一條規則：帶著目標進來就不再讓人選
②Merge 來源清單要不要加 remote branch？使用者裁定 2026-10-08：「裁定2加入origin選項」。02-A 已加 REMOTE BRANCHES 組（與 Rebase 一樣列 session.refs.remoteBranches）。要（例如 merge origin/main 是常見操作）。現在只列 local；02-A 畫的是只有 local，你點頭我再加 REMOTE 組
③ro 欄的 commit 計數使用者裁定 2026-10-08：「1,3,4,5,6,7照你建議，8一起做」。本輪不畫（需要新的 core 查詢）；要的話另開一輪
④發現：05-E commit 列的 Merge into current 直接 merge，不開對話框使用者裁定 2026-10-08：「1,3,4,5,6,7照你建議，8一起做」。更正：本稿原本對 ④ 沒有給建議，只問了你。不在這次回報範圍，只是報告；要一起改成開 02-B 的鎖定版嗎？ 補上的建議：不改——05-E 的標籤 Merge into current 沒有 …，依 [UX-ellipsis-promises-a-dialog] 不承諾對話框；它直接以 --no-ff + git 預設訊息合入
⑤ro 欄位要不要框線？DLGS 有 1px --border-default，app 無使用者裁定 2026-10-08：「1,3,4,5,6,7照你建議，8一起做」。照 app（無框），因為 Checkout 的「目前」列等既有 ro 欄都已出貨無框；要改就全部一起改
⑥標題與主按鈕文字（DLGS vs P06 vs app）使用者裁定 2026-10-08：「1,3,4,5,6,7照你建議，8一起做」。本輪不動，維持 app 的 Merge Branch / Rebase / Start rebase
⑦預設訊息格式：DLGS 合入 main 畫的是 Merge branch 'feature/lane-allocator'。但 git 2.56 的預設（man git-fmt-merge-msg：未設 merge.suppressDest 時只省略 master）合入 main 會寫 Merge branch 'X' into main 更正（實測 git 2.56，2026-10-08）：合入 main、master 都省略目的地，合入其他分支才加 into <目前>；來源是 remote 時是 Merge remote-tracking branch 'origin/x'。DLGS 的例子與 git 一致使用者裁定 2026-10-08：「1,3,4,5,6,7照你建議，8一起做」。建議：完全照 git 的預設格式（含 into 與 remote-tracking branch 兩種變化），使用者看到的就是 git 自己會寫的訊息
⑧DLGS hint「squash 時改為多行欄位並帶入來源 commit 摘要」——app 現在 squash 時把訊息欄停用使用者裁定 2026-10-08：「8一起做」。見 02-C。摘要取自 gbm_request_compare_refs(HEAD, 來源, threeDot=0) 的「來源有、HEAD 沒有」commit 清單
⑨squash 訊息的格式，以及 squash 後要不要直接建 commit使用者裁定 2026-10-08：「用 git 的 SQUASH_MSG」；squash 後是否 commit：「merge沒conflict才可以直接commit」。02-C 已改畫 SQUASH_MSG（"Squashed commit of the following:" + git log --pretty=medium HEAD..<來源>，實測與 git 寫的逐位元相同）。提案（Inferred，spec 只寫「帶入來源 commit 摘要」）：首行 Squash merge branch '<來源>'，空一行，每筆 * <subject>（舊到新）。既然有訊息，squash 後就用它直接 commit（現況只 stage、不 commit；app 副標「不記錄 merge commit」改為「合成一筆一般 commit」）
