流程

按下 Create repository 之後

目標路徑 = 位置 / 名稱。git 行為是在 git 2.56.0、暫存目錄實測的結果。

對話框關閉
  │
  ├─ git check-ref-format --branch <預設分支名>   不合法 → 不建目錄，Log 寫 error（N-D3）
  ├─ git init --quiet -b <預設分支名> <位置/名稱>   失敗 → Log 寫 error，結束
  └─ Log：Created a repository at <path> → 轉到新 repository
情況git 實測對話框怎麼處理
新路徑init -b trunk fresh exit 0，HEAD 是 refs/heads/trunk；缺的上層目錄 git 自己建a
目錄存在、不是空的、不是 repositoryexit 0，原本的檔案變成 untracked（?? a.txt）d：可以建，先用 warn 說清楚
已經是 repositoryexit 0，印 warning: re-init: ignored --initial-branch=other，HEAD 不變c：停用。git 不會報錯，但 -b 不會生效
分支名不合法（a..b）exit 128 fatal: invalid initial branch name，但目錄已經被建出來、留在磁碟上先跑 check-ref-format，不合法就不跑 init（N-D3）

推測值

沒有出處、我自己填的值

  • c、d 的 warn 欄位本身：DLGS 的 New repository 條目沒有 warn，是 N-D2 的裁定加上的；位置放在最後一欄之後。
  • c、d 的 warn 文字「<path> 已經是 git repository。」「<path> 已存在且不是空的，會在現有檔案上建立 repository。」：句型仿 add_worktree_dialog.dart:561。
  • 「第一個來源資料夾」讀成「第一個啟用的來源資料夾」，和 Clone 的 _defaultParent() 一致；沒有啟用的來源資料夾時位置欄空白。
  • 名稱欄的限制：不可空白、不可含 / 或 \、不可是 . 或 ..；不符合時按鈕停用，不另外寫字。名稱、位置、預設分支名任一空白時按鈕也停用。
  • 「瀏覽…」與 hint 的位置：hint 放在輸入框與按鈕那一列的下方。和 Add worktree 一樣 更正（spec-auditor）：Add worktree 的位置欄沒有 hint；這個順序的出處是 P17 欄位模板（label → 控制列 → hint）與 Clone 現在的畫法。
  • 按鈕圖示：畫的是 worktree-dialogs-spec.html:567 的資料夾圖示（關起來的資料夾）、13px；實作沿用 Add worktree 的 Icons.folder_open_outlined，不照這裡的路徑與尺寸。
  • 四個畫面的範例值：graph-bench / ~/src / main 是 DLGS 原值，其他是示意。
  • 勾選框的白色勾號（Clone）：照已核定的前例頁畫法，實作用 Flutter Checkbox。

#問題裁定 / 建議
N-D1「從全域範本」的範本是什麼（git 沒有全域 .gitignore 範本）裁定「拿掉這個勾選」
N-D2目標路徑已存在裁定已是 repository → 停用 + warn；存在且非空 → 可以建 + warn；空目錄照常
N-D3分支名不合法時 git 會留下空目錄裁定照建議：core 先跑 git check-ref-format --branch，不合法就不跑 init
N-D4空 commit 的細節裁定「不要新建commit」→ 拿掉「建立第一筆空 commit」，New repository 不建任何 commit。使用者確認（2026-10-23）「對，拿掉空 commit 勾選」
N-D5按下去之後裁定照建議：按下就關，成敗只進 Log
N-D6預設分支名的初值裁定照建議：固定 main
N-D7外框數值 P6 mock、P6 文字、app 三方不同裁定沿用現有 GbmDialogShell；要不要改 shell 另案
