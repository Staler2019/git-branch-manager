項目規則出處
工作目錄永遠是被選取的 worktree 路徑，所以 rider .、explorer . 直接可用desktop_launcher.dart openTerminal 的 workingDirectory: path
{path}macOS/Linux：換成參數 "$1"，路徑本身不進 shell 字串，所以路徑含空白、引號、$(…) 都不會被執行。Windows：換成 .（工作目錄就是 worktree），路徑完全不進 cmd 字串。寫成 "{path}" 或 '{path}' 時存檔就正規化成 {path}；其他位於引號內的 {path} 不能存檔（否則 ""$1"" 等於沒有引號）desktop_launcher.dart「never interpolated into a shell string」 · security review F2、F4 · 置換語法 新增
macOS / Linux$SHELL -lic '<指令>' gbm <worktree 路徑>，stdin 接 /dev/null。只有 $SHELL 是絕對路徑、而且是 sh / bash / zsh / dash / ksh / mksh / yash / ash 時才用它，其他（fish、pwsh、tcsh、nu…）一律 /bin/sh，因為那些 shell 的 $1 語意不同。用 -lic：login + 互動，~/.zprofile 和 ~/.zshrc 裡的 PATH（nvm、pyenv、conda）都拿得到；GUI 啟動的 app 預設只有 /usr/bin:/bin:/usr/sbin:/sbin。已知代價：.zshrc 裡若有 exec tmux 之類的寫法，指令不會執行；stdin 接 /dev/null 讓互動提示直接讀到結尾、不會卡住login shell 裁定 · -lic 裁定 D6 · 白名單：security review F3
Windows%SystemRoot%\System32\cmd.exe /d /s /v:off /c <指令>，經過既有的 startDetachedProcess relay，workingDirectory 是 worktree。worktree 是 UNC 路徑（\\server\share）時不執行並回報失敗，因為 cmd 不能把 UNC 當工作目錄，會退回 C:\Windows。指令含雙引號 " 時也不執行並回報「Windows 上的指令不能含雙引號」：relay 會拒絕任何含 " 的參數，像 "C:\Program Files\…\code.cmd" . 這種寫法在 Windows 一定失敗，所以先擋下並說明detached_process.dart startDetachedProcess、windowsRelayShell 的絕對路徑 · 雙引號 detached_process.dart:72 · security review F2、plan review
指令本身是使用者自己寫的，會原封不動交給 shell。這是刻意的：等同使用者在 terminal 裡打同一行裁定「經由使用者的 login shell」所選選項的說明：「用 $SHELL -lc '<cmd>' 執行，PATH 跟你在 terminal 裡看到的一致」

裁定 · 2026-10-18

六個決定

#問題裁定
D1選單裡要不要顯示每一項的指令「只顯示名稱」
D2Preferences 段名與位置「External apps」，放在 Appearance 之後
D3怎麼知道執行失敗「最多等 5 秒看結束碼」
D4預設清單「放檔案管理員」：Finder open . / Explorer explorer . / xdg-open .。追問「"." 都可以用{path}取代嗎？ windows 不行？」的答覆：兩邊都能寫；Windows 上 {path} 會換成 .（security review F2），效果相同，只有一定要絕對路徑的程式在 Windows 上不適用
D5選單最後一項的文字「Edit apps…」
D6login shell 拿不到 .zshrc 裡的 PATH「我的需求是 lic 才做得到」→ 改用 -lic，stdin 接 /dev/null
