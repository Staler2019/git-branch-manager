Commit 框帶入 git 準備好的訊息

merge 衝突解完、或 squash 只 stage 沒 commit 時，git 早就在 .git/MERGE_MSG / .git/SQUASH_MSG 寫好了訊息。core 的 readPreparedCommitMessage() 會讀，但從 Qt 版移除後就沒有人呼叫它（[CULT-orphan-wiring]）。這份稿子讓 Working Copy 的 commit 框重新帶入這段訊息。框本身的外觀完全不改，改的只有什麼時候、填什麼。

G1 · 全部已裁定（①～⑮） 版面：0 個新元件 實測：git 2.56.0
01

什麼時候會填

使用者裁定 2026-10-09：「衝突解完會回到 working copy 決定是否 commit，所以 commit message 必須先是 merge 預設，會覆蓋如果使用者早有填入 message 的情形」、「merge 發生時就換 MERGE_MSG」。
所以 docs/FEATURES.md 的「without overwriting anything the user has typed」，以及 PreparedCommitMessage.h 的設計 C3「不得覆蓋使用者已經打好的 commit message」，都已被這次裁定推翻；實作時兩處都會在原處改寫。

git 寫下訊息 app commit 框 ───────────── ─── ───────── merge 衝突 MERGE_HEAD+MERGE_MSG ─┐ squash 衝突 SQUASH_MSG+MERGE_MSG ─┤ RepoState.preparedMessagePending squash 只 stage SQUASH_MSG ─┤ （兩次 stat，不讀內容） squash commit 失敗（hook） SQUASH_MSG─┘ │ │ false → true 的那一刻（merge 發生時） ▼ 不在 amend 模式 → 請求訊息 │ gbm_request_prepared_commit_message ▼ PREPARED_COMMIT_MESSAGE_READY {message} （已經用 stripspace -s 去掉註解行） │ 原本框裡的字先存起來（同 amend 的 preAmend） ▼ 覆蓋：第一行 → Summary，其餘 → Description ┌────────────────────────────┐ │ Merge branch 'feature/…' │ └────────────────────────────┘ 之後使用者在框裡改的字 → 保留（每個 merge 只填一次） Commit 送出 → git 刪掉 MERGE_MSG／SQUASH_MSG → pending 變成 false → 框照舊清空 Abort → pending 變成 false → 框還是自動填的內容 → 放回 merge 前存起來的字（裁定 ③＋⑨）

#情境結果影響
M1merge 衝突（不論有沒有給 -m）後的 MERGE_MSGMerge branch 'topic'\n\n# Conflicts:\n#\tf\n註解行會進框

M4同一個 squash 衝突解完後，git commit（editor 流程）自己寫進去的訊息SQUASH_MSG 的全文，MERGE_MSG 的註解行被 strip 掉。也就是 git 的組法是 SQUASH_MSG 接 MERGE_MSG，再做 strip照抄這個順序
M5git stripspace -s，設定 core.commentChar=;只去掉 ; 開頭的行，#123 mine 留下R1 交給 git 做，不在 Dart 裡寫死 #

#問題結果
①# 註解行；使用者已打的字要不要覆蓋使用者裁定 2026-10-09：註解行「其他照你建議」→ R1（core 用 git stripspace -s 去掉註解行）。覆蓋：「commit message 必須先是 merge 預設，會覆蓋如果使用者早有填入 message 的情形」。原建議：框裡有使用者的字就不覆蓋（C3）
②什麼時候填使用者裁定：「merge 發生時就換 MERGE_MSG」。原建議：衝突清單清空時
③Abort 之後框裡的字使用者裁定：照建議。框還是自動填的內容就清掉；使用者改過就留著。清掉之後放回什麼，見 ⑨
④merge 中的 Amend…使用者裁定：「merge 時，amend 按鈕不應該出現」→ 不顯示。原建議：停用並加 tooltip。註：spec 有一句「disabled，並附 tooltip 說明原因，不隱藏」（講的是選單項目和多選），這次照你的裁定。squash 等待中沒有 MERGE_HEAD，git 允許 amend（M7），所以照常顯示
⑤取 ours 後 Commit 被停用使用者裁定：照建議。merge 進行中不要求 staged 非空
⑥P8 的 Continue 與 merge使用者裁定：「merge 時有可能會 conflict……如果不需要解衝突，應該最上面 warning 列只會有 abort 按鈕，沒有 continue 按鈕」→ 02-C：merge 的 banner 不顯示 Skip／Continue（現況是顯示但停用）；有衝突時 Resolve… 開衝突視窗（現況已是如此）。不另做 merge 的 Continue 訊息步驟，commit 一律回 Working Copy
⑦C++ 的 shouldApplyPreparedCommitMessage()使用者裁定：照建議。刪掉；覆蓋規則改成 ①，判斷寫在 Dart
⑧訊息怎麼送到 Dart使用者裁定：照建議。RepoState.preparedMessagePending 加上請求／事件
⑨① 會蓋掉使用者原本的字，Abort 時要放回來嗎？使用者裁定：照建議。放回：做法和 Cancel amend 一樣（preAmendSummary），merge 前的字存起來，Abort 後框還是自動填的內容就換回去。不放回的話，使用者在 merge 前打的字會因為一次 Abort 就消失
⑩revert 的 banner 也是 Skip／Continue 顯示但停用（canSkip／canContinue 對 revert 都是 false）使用者裁定：照建議（02-C2）。一起改成不顯示：banner 用同一個規則「不能用的就不畫」；Abort 對 revert 也是停用（canAbort false），一併不顯示。也可以只改 merge，由你決定
⑪app 啟動時 merge 已經在進行使用者裁定 2026-10-09：「我要預設覆蓋使用者已填的訊息，但設 feature flag 開關」→ 啟動時也覆蓋；Preferences → Git 加開關 overwriteWithPreparedMessage，預設開（02-E）。關閉時只有框是空的才帶入。原建議：框是空的才填。附註：開著的時候，merge 中途改好的訊息在重開 app 後會被蓋回 git 的預設
⑫commit 框樣式使用者裁定：「commit message 你說的 style 問題順便修」→ 02-D，改用 app 已有的 gbmInputDecoration／gbmMultilineInputDecoration（radius 6、border-default、surface-panel 底、focus 時 accent），summary 用 h30、text-sm
⑬placeholder 的顏色。kit 寫 .gbm-input::placeholder{color:var(--text-tertiary)}，但這兩個共用 helper 沒有設 hintStyle，所以 全 app 約 15 個輸入框 全 app 用這兩個 helper 的 21 個輸入框（其中 17 14 個有傳 hintText，spec-auditor 逐一列舉）的 placeholder 都還是 Material 預設色使用者裁定：照建議。在兩個 helper 裡補上 hintStyle（text-tertiary）

⑮P3 縮小 mock 和 app 還有其他不同：placeholder 是中文（「Summary（50 字內，subject 行）」）、按鈕寫 Commit 1（帶數量）和 Amend（沒有 …）、commit 區底色是 surface-panel-raised使用者裁定 2026-10-09：「15 的除了中文問題，其他修」→ 按鈕改成 Commit N（N = staged 檔數） 使用者裁定：「不需要 commit n，把它改回 commit 就好」→ 維持 Commit；Amend… 改成 Amend（不帶 …）；commit 區底色改成 surface-panel-raised。placeholder 維持英文。注意：拿掉 … 之後，進入 amend 模式的按鈕和 amend 模式裡送出的按鈕都叫 Amend（兩者不會同時出現）。另外 Amend… 拿掉 … 也符合 [UX-ellipsis-promises-a-dialog]：它只是進入模式，不開對話框
