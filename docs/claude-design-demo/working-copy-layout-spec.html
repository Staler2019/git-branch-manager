01

The complaint, and what actually causes it

「目前左右不好看檔案內容」 — the file content is the thing that needs width, and today it is the only thing that never gets any.

The Working Copy is split top/bottom: file lists above, diff below. The file lists are then split left/right into Unstaged and Staged. So the diff gets 54% of the height and 100% of a width it did not need to share — while two columns of file paths, which are short, get the full width above it. Then the diff pane splits itself left/right again for 2 file mode, and the code that actually has to be read ends up in a box roughly a quarter of the window.

Rotating both dividers fixes it without adding a single pane: file paths are short and stack happily; a diff is tall and narrow-hostile. The stack gives the diff a full-height column and every pixel the window gains from then on.

Not a conformance fix

Everything on this page is a deviation the user asked for, in the same standing as the Working Copy's removed checkboxes. Section 06 quotes exactly what it overrules, so a later audit reads it as ratified rather than as drift to be repaired.

05

The drop hint has to change, and has nothing to quote

「拖曳檔案到右欄 = stage」 — once Staged is below rather than beside, 右欄 is simply false. A hint pointing the wrong way is worse than no hint: it is a control that lies.

#CandidateArgument
C1拖曳檔案到下欄 = stage Recommended. One character changes — 右 → 下. Keeps the spec's own sentence shape, its =, and its word 欄, so the deviation is as small as a deviation can be while still being true.
C2拖曳檔案到下方 = stage 下方 reads slightly more natural than 下欄 for something stacked, but abandons the spec's noun. Marginally better Chinese, marginally further from the source.
C3往下拖 = stage · 往上拖 = unstage Says both directions, which the current hint never did — the Staged pane has no hint of its own and unstaging is undiscoverable. Honest, and the biggest departure: new information, not a corrected word.
Ruled — C1

「拖曳檔案到下欄 = stage」. One character moves, 右 → 下; the sentence shape, the = and the noun 欄 all stay the spec's. The mockups in sections 02 and 03 already draw it. The Staged pane still has no hint of its own — C3 was the candidate that would have added one, and it was not the one chosen, so unstaging stays as discoverable (or not) as it is today.

A rule this comparison proved stale

[STRUCT-working-copy] says the one-shot scope is 「rendered in a fixed slot at the top」. It is not, and has not been since the round that nested it — the DOM above and scoped_diff_view.dart's own doc comment agree with each other and not with the rule. Corrected in place as part of W9 rather than filed as work, because there is nothing to build: the code is already right and only the record is wrong.

Needs a ruling — six of them, and a default for each
  • S3 dashed lines — recommend adopting. The dash is not decoration: it is what separates 臨時選取's 一次性 block from the solid-edged cards that persist. Today both are solid and only the colour differs.
  • S4 card head — recommend adopting the bottom border (the head reads as part of the code without it) and the muted head's sunken ground; the fixed 30px height recommend leaving as it is, because the head is a Wrap that is allowed to take a second line in a narrow pane, and a fixed height would clip it — which matters more now that the pane is a right-hand column.
  • S5 column head — recommend adopting the chip and the 8px dot, and leaving the title at textXs/bold/secondary, which is what every other pane header in this app uses; matching the design here would make this one header unlike its neighbours.
  • S6 +N −M — recommend keeping the badges, and this is the one place a difference is recommended against the design on its own merits rather than on consistency. 變體 B writes .variant-B-plus { color: var(--diff-add-strong) }, and --diff-add-strong is the pale background tint — #bfe9cd light, #173e24 dark. As a text colour on the head's own panel-raised ground that is #173e24 on #161b22 in the theme this app ships in: all but unreadable. The specimen above draws it as written, which is why the left-hand figures look absent. Consistency points the same way — the two file lists beside this pane draw the identical fact as a GbmBadge.
  • S7 (N changed) — recommend keeping it. 匡選行數 and 實際變動行數 are different numbers and the button moves the first; the design's shorter label is only unambiguous when they are equal, which is exactly when the code omits the parenthetical anyway.
  • S8 一次性 chip — recommend adopting the warning outline. It is the one thing on screen that says 「這個按下去就 沒了」, and a neutral pill is the same shape as the count badges beside it.
  • S9 hunk rule · S10 margin · S11 hover — recommend adopting all three; each is one property, and hover is the one dimension-D signal the card currently has none of.

Taking every recommendation above is W11–W13 in section 08, three commits. Rejecting any of them removes lines from those commits and adds nothing; scoped_diff_view.dart is not touched at all until this section is ruled on, so the rest of the round can proceed in the meantime.

Acceptance

  • A layout test asserts Unstaged's rect is above Staged's and the files column's right edge is at or before the diff's left edge — both against the neighbour, so the test cannot pass by matching a constant that also moved.
  • A test asserts the commit box is still the last child and still spans the full width. This is the only mechanical statement of 「位置不變」.
