Author 欄位比對 Preferences 的 user.email（含 repository 層級的 override）。相符的列，author 以 accent 色 + semibold 顯示，其餘作者維持 tertiary 灰。

Graph 連線規則
目前開發中的分支永遠佔 lane 0，且是一條從頭到尾不轉折的直線。其他分支一律往右配置，轉折全部發生在支線那一側，主線不會為了讓路而歪掉。
分岔與合併用貝茲曲線接進 lane 0，曲線的顏色屬於支線，不是主線，這樣一眼看得出是誰併進來。
Lane 顏色以該 lane 的起始 commit 為 key，不是 lane 索引，所以捲動或重新整理後同一條分支顏色不變。
超過 48 lane 時右側顯示 overflow 標記與實際被省略的分支數，不做無聲截斷。
怎麼看出 local 與 origin 的位置
位置由 commit 列上的 ref chip 表示。local 與 origin 在同一個 commit 時只出一個 chip，尾端加一個雲朵圖示代表遠端也在這裡，不再另外寫一次 origin/ 前綴——同一件事寫兩遍只是佔寬度。
feature/graph-lanes ☁ 實心加雲＝本機與遠端同步於此。
HEAD → main 實心加外光暈但沒有雲＝目前 HEAD，且遠端不在這裡；該節點另套一圈外環。
origin/main 虛線外框＝只有在分歧時才會出現，標出遠端落在哪個 commit。
所以看到虛線 chip 就代表有差距，兩個 chip 之間的節點數就是差幾個 commit；toolbar 的 ↑2 是同一件事的數字版。
Commit description 在哪裡看（第 7 題）

為什麼 repo 不跟 branches 放一起
切 repo 是低頻但影響整個視窗的動作；選分支是高頻且只影響中央內容。兩者混在同一份可捲動清單時，分支多的專案會把 repo 擠到看不見，而 repo 多的人每次找分支都要先捲過一段無關內容。
拆開之後：sidebar 永遠只描述目前這個 repo，四段結構固定不變，Ctrl/Cmd+Shift+E 的 branch filter 也只需要處理分支語意；repo 則收進一顆常駐顯示目前位置的按鈕，按 Ctrl/Cmd+R 隨時叫出，選完即關。
彈窗而非 modal dialog：切 repo 不需要中斷式的確認，Esc 關閉即回到原狀，不改變任何狀態。

點行套用的順序規則（第 8 題核心）
整段套用用 hover 出現的 → / ← 鈕，或把整段拖進中欄。
單行套用則是直接點該行：第一次點的行進到結果的上面，第二次點的行接在下面，依此類推，中欄以 ①②③ 標示順序。
所以「左 → 右」與「右 → 左」點擊順序不同，產生的結果檔行序也不同——這是刻意的，取代傳統 both-sides 按鈕的兩個固定選項。
套用後的行可在中欄按行尾的刪除鈕或拖出中欄 discard，序號會自動重排。整段 discard 用 Ctrl/⌘+Z 復原。
解完之後的 commit message — 自動帶入預設值
全部檔案標記 resolved 後按 Continue，不直接送出，先開一個 commit message 步驟，訊息依作業種類預先填好，游標停在訊息結尾、全文可改。使用者若清空 summary，按鈕會停用而不是偷偷用預設值送出。

{{ icErrBig }}
無法推送到 origin/main
遠端比本機多 3 個 commit。直接推送會覆蓋別人的紀錄，因此 git 拒絕了這次操作。
{{ icChevDown }}git 的原始輸出
$ git push origin main ! [rejected] main -> main (non-fast-forward) error: failed to push some refs to 'origin' exit 1 · 0.84 s
主要按鈕永遠是下一步的動作，不是 OK。
什麼時候才開視窗
預設不開。錯誤先進 log，並在 status bar 留一則常駐可點的摘要（10-3）。只有兩種情況升級成視窗：使用者剛剛主動按下的動作失敗了，或需要使用者做決定才能繼續。
背景作業（自動 fetch、掃描、LFS 抓取）失敗一律不彈窗——沒有人按過按鈕，就不該打斷。

錯誤訊息的寫法
標題寫哪個動作失敗了，用產品的話；內文寫為什麼，一到兩句，講具體條件與實際數字（多 3 個 commit），不寫「發生未知錯誤」。
git 的原始輸出一定保留，摺疊在下方、等寬字、可選取複製。翻譯過的說明不取代原文，因為排查時需要真正的那行字。
Copy details 複製的是標題、原始輸出、指令、exit code 與時間戳，貼進 issue 就夠用。
同一個錯誤連續發生不重複開窗，改為在既有視窗上累加次數。視窗不阻擋其他 repo 的操作。
取消的語意
取消永遠不刪已經存在的東西。Fetch 取消保留已抓到的 objects，下次續傳；History 掃描取消保留已載入的部分並在頂端註明「已載入 40,000 / 199,960，捲到底可續掃」。
唯一會刪東西的是 clone 取消——因為目標資料夾是這次動作建立的——log 會寫明刪除的路徑。
會改寫 working tree 的作業（checkout / merge / rebase）不提供取消，取消鈕直接停用並附原因，不做成按了沒反應。
所有截斷與上限一律顯示實際數字，不做無聲截斷。

多選的共通規則
單選是多選的特例：所有清單一律維持一組 selection + 一個 anchor，Shift 以 anchor 為起點取範圍，Ctrl/Cmd 逐項切換並把 anchor 移到最後點的那一項。
右鍵點在已選中的項目上不改變 selection，選單標題顯示數量；點在未選中的項目上先改為只選它、再開選單，避免對看不見的選取做動作。
對多選只出現「對每一項都有意義」的動作。單項專屬動作（Rename、Checkout、Set upstream）在多選時保留但 disabled，並附 tooltip 說明原因，不隱藏 — 隱藏會讓人以為功能不存在。
commit 多選只在連續範圍時開放 cherry-pick / revert / squash；不連續時這三項 disabled，tooltip 寫「選取需為連續 commit」。狀態列一律寫出是否連續。
破壞性批次動作（Delete branches、Drop stashes）的確認 dialog 逐項列出名稱與未 push 的 commit 數，並區分「本地」與「遠端」兩份清單，不用一句「刪除 3 個分支？」概括。
批次執行依序進行、失敗不中斷其餘項目；結束後在 P10 背景列給一行結果摘要（例如「刪除 3 個分支：2 成功、1 失敗」），失敗項可從錯誤視窗重試。
Selection 在切換分頁與重新整理後保留，切換 repository 時清空。Esc 縮回單選（保留 anchor 那一項），Ctrl/Cmd+A 全選當前清單。
